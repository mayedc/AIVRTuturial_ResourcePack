# Cursor prompt · Install, update, start and prove both MCP connections

Work with two **open empty applications**: a new Blender startup scene and a separate **temporary blank** Unity project. Do **not** open the cloned workshop Unity project yet. Read `Docs/Cursor_First_Workflow.md` and upstream READMEs for `https://github.com/CoplayDev/unity-mcp` and `https://github.com/ahujasid/mcp-for-blender` using official sources.

1. Inventory current `uv`/`uvx`/Python, Blender add-on, Unity `com.coplaydev.unity-mcp`, their actual versions/commits, Cursor MCP servers and any local overrides. Back up nonempty configurations; never replace all MCP servers. Find the latest **compatible stable** upstream version rather than blindly using a development branch.
2. **Blender:** if missing, install `uv` via official install instructions (Windows option `winget install --id=astral-sh.uv -e`), reopen terminal, then run official `uvx mcp-for-blender setup` selecting Cursor; for an installed older version use `uvx --refresh mcp-for-blender setup` after checking changes. Use `uvx mcp-for-blender install-addon` only as needed. Prefer supported installer over cloning arbitrary files into the workshop project. Keep `uvx` and add-on versions compatible and record both. Preserve existing server configuration.
3. **Unity:** check for the UPM `com.coplaydev.unity-mcp` package. If absent, install through Package Manager Git URL `https://github.com/CoplayDev/unity-mcp.git?path=/MCPForUnity#main`, or a selected compatible stable release. If present but older, back up manifest/lock and upgrade just the MCP dependency to a compatible tested version; wait for compilation and revert only MCP if it fails. Do not vendor the GitHub repository into `Assets`.
4. Ask the student to open Blender's **MCP for Blender** sidebar and Unity's **Window → MCP for Unity** window; enable/start each local service. In Unity use **Configure All Detected Clients** or use the actual shown local endpoint to configure Cursor. Avoid exposing local services to network interfaces. Restart Cursor fully if config changed.
5. Discover the **actual** Cursor MCP tools. Make a read-only tool call to Blender returning version + file path + object count, and a separate read-only Unity tool call returning project path + Editor version + active scene + Console error count. Distinguish tool-unavailable, server-down, application-down and permission problems. If any check fails, use the troubleshooting loop in `Docs/Cursor_First_Workflow.md`, make a minimal fix and **retry the live calls**.
6. Finish with exactly two explicit lines: `Blender MCP: CONNECTED / FAILED / NOT TESTED — evidence: ...` and `Unity MCP: CONNECTED / FAILED / NOT TESTED — evidence: ...`. Report whether the connection refers to the **empty Unity sandbox**; a second verification will be required when switching to the workshop project. Never claim success solely from a config file, installed package, port, or terminal command.
