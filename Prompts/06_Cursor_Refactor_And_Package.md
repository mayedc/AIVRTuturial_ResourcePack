# Cursor prompt — safe identifier cleanup, package export and clean import

Run on a **separate local teacher copy** using Unity, Cursor, and actual MCP tools. Never rename the shipped Unity asset folder through GitHub's web UI alone. Read `AGENTS.md`, `Docs/ProjectArchitecture.md`, `Docs/03_Unity_Integration.md`, `Docs/AssetManifest.md`, `Packages/manifest.json`, `ProjectSettings/ProjectVersion.txt`, `Tools/ValidateRepository.ps1` and current Git status. Commit or back up the starting state first.

**1. Inventory and plan.** Find *debug/iteration suffixes* (for example `AI_VR_Workshop_V4`, `AIVRWorkshop.V4`, `Workshop V4`) in directory names, C# namespaces, assembly definition names/references, editor menu labels, project/scenes, serialized data, build settings, YAML, scripts, paths, docs, prompts and validation tools. Separate these from legitimate archival release tags (`v1.0.0`) and filenames for sequential student checkpoints. Explain the proposed rename map, e.g. `Assets/AI_VR_Workshop_V4` -> `Assets/AI_VR_Workshop`, `AIVRWorkshop.V4` -> `AIVRWorkshop`, `Workshop V4` -> `Workshop`. Search for extra names before applying; do not blindly strip all digits.

**2. GUID-safe rename in Unity.** Close the Editor before filesystem operations if necessary or prefer AssetDatabase MoveAsset / Unity Editor operations for folders, assets and assembly definitions. Preserve `.meta` GUIDs and move matching `.meta` files together. Update `.asmdef` names/references, namespaces/usings, qualified serialized type references, editor menu items, `ProjectSettings/EditorBuildSettings.asset`, validator roots, scripts, tools, README and relative links. Keep teacher scenes and functionality intact. Do not rename source art, root repository, release tags or public third-party packages without a clear reason.

**3. Validate the rename.** Reopen in a compatible Unity 6 Editor; wait for import, confirm zero C# compile errors, check the active scene, prefab/MonoBehaviour references, menu commands and Console. Validate scene copies, Play Mode crossing/robot/gap/pause/restart and the speed/flight teacher reference separately. Use `git diff --check`, repository validators, and grep for residual **active** V4 names; explicitly list any archival references left for historical accuracy. Do not push if GUIDs or scenes are broken.

**4. Make a reusable package.** Export a **tested `AI_VR_Workshop.unitypackage`** from the Unity Editor (Assets > Export Package, include dependencies). Include scenes, prefabs, materials, scripts, editor tooling and required workshop assets; identify external Unity/Meta/OpenXR package dependencies rather than illegally bundling them. If the MCP can perform export reliably, use it; otherwise run a reviewed Unity Editor script/batch method or have the teacher export it in the GUI. Put distribution outputs in a teacher-approved release location, not arbitrarily into a student Assets folder.

**5. Clean install round trip.** In Unity Hub, create a **new blank URP project** at a compatible or newer tested Unity Editor version. Import the exported package; install any declared UPM dependencies and MCP bridge; verify that the student can add the Blender FBX and use MCP to populate a scene without opening the original whole Unity project. Run compilation, validation and desktop Play Mode. If script insertion through MCP fails, demonstrate the **manual .unitypackage import** and MCP revalidation path.

**6. Report and commit.** Show changed files, newly created package, clean Unity test logs, status of every gate and unresolved issues. Commit only authorized source changes and safe artifacts. Do not claim a Quest device test or MCP connection unless performed on real applications.
