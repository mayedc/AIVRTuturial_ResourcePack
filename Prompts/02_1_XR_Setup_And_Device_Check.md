# Prompt 02_1 — Inspect and prepare XR, Meta camera assets, and Quest Link (NO scene binding)

You are the classroom Cursor Agent. The student has already **tested and passed Prompts 1.1–1.4**, including the complete desktop vehicle route and speed/flight interactions. Reply in **Simplified Chinese**. **Run only 02_1**; do not place, parent, reposition, instantiate, or replace any XR camera or rig in the workshop scene. Never automatically start 02_2.

## Objective and safe scope

Check **this machine and the actual Unity project currently open** (prefer the student's working project, not the teacher GitHub original). Use live Unity MCP readbacks, Unity Package Manager, Project Settings, local configuration and read-only project inspection. Avoid whole-drive scans. Preserve the verified desktop scene/scripts and all existing packages and user settings. Unity XR provider/Initialize XR settings are **project-wide**: before changing them, make a project/manifest/settings backup and, if necessary, use a **separate student VR project copy** so desktop 1.1–1.4 still works without an HMD.

### A. Inspect first; report what is already present

1. Via Unity MCP confirm editor version, absolute active Unity project path, active scene, build target, Console compile errors, active XR subsystem status and existing camera hierarchy. Confirm the desktop tests are still recorded; never claim a live test simply from the student's earlier report.
2. Check **Edit > Project Settings > XR Plug-in Management**, specifically **Windows/Mac/Linux (Standalone)**, whether XR Plug-in Management is installed, **OpenXR** loader/provider is enabled, **Initialize XR on Startup** in the designated VR project, and **OpenXR project validation / Meta XR feature group** as applicable for the installed SDK. Distinguish installed package from enabled loader and initialized runtime. For this Windows wired PCVR lesson do **not** confuse the Android build-target settings with the required Standalone settings.
3. Inspect **Window > Package Manager > In Project** and the active `Packages/manifest.json` / lock for `com.unity.xr.management`, `com.unity.xr.openxr` and **Meta XR Core SDK** (`com.meta.xr.sdk.core` or its installed package identity). Report their detected versions and conflicts. Unity OpenXR is the preferred modern provider; **do not install the deprecated Oculus XR Plugin** as a default workaround.
4. **Core asset requirement:** actually find and inspect a usable, non-missing camera rig prefab/asset (prefer Meta XR Core's `OVRCameraRig` or the supported Meta XR Rig / Building Block provided by the installed SDK). Search only Unity's AssetDatabase/Package Manager and relevant project folders; inspect prefab hierarchy for a tracked **CenterEyeAnchor/CenterEye camera**, tracking component(s), and their resolved script references. An XR loader alone, a broken `Workshop_MetaVR.unity` reference, or a text reference to a Meta GUID is **NOT** proof that the rig exists. Do not create/place a rig at this stage.
5. Check Windows Quest Link / Meta Horizon Link PC application installation/status, availability of Quest 3/3S, a working **USB data cable**, device connection status, active **PC OpenXR runtime** and (when visible) actual **Link session started**. Report separately: physically detected, app recognized, Link active, OpenXR runtime selected. Never label a device connected based only on USB charging or a paired-device listing.

### B. Repair only missing or incompatible pieces

6. **Already available and healthy:** keep installed packages/prefabs/runtime and report **READY**. Do not reinstall, add duplicate rigs, overwrite manifest/lock, or upgrade just to change a version number.
7. If **XR Plug-in Management or OpenXR is missing/disabled**: with the student's knowledge and a backup of the student VR project, install/enable a **compatible-or-newer validated** `com.unity.xr.management` and `com.unity.xr.openxr` using Unity Package Manager / Project Settings. Select **OpenXR under Standalone**, resolve Unity/OpenXR Project Validation and enable the appropriate Meta XR feature group when required. Configure **Initialize XR on Startup** **in the VR project copy only**, keeping the desktop project unaffected. Verify after Unity recompiles.
8. If **Meta XR Core / VR camera prefab is missing**: explain the required asset. Use the **official Meta XR Core SDK** via the **Unity Asset Store > Add to My Assets > Open in Unity > Package Manager > My Assets > Download/Import or Install**, according to the current Unity UI and license. Ask the student to sign in/accept any licensing prompts manually; Cursor must not automate purchases, accept agreements, or download unofficial binary mirrors. Once installed, recheck the **actual** Meta package, prefabs, missing scripts, and Console. Do not assume that installing OpenXR automatically downloads Meta Core.
9. If **Quest Link is not connected**: provide these **student-visible steps** rather than claiming Cursor can connect the headset:
   - Open the installed **Meta Quest Link / Meta Horizon Link** desktop app on Windows and sign in manually.
   - Connect Quest 3/3S to the PC with a **USB-C data cable** and a capable USB port; confirm the device appears in the PC app (run its cable/USB connection test if offered).
   - Put on the headset; from its notification or **Quick Settings > Link / Quest Link** (menu wording may vary), **Enable/Launch Link** to enter the **PC Link environment**. A USB file-access dialog is not the same as starting Link.
   - In the PC Link app, inspect **Settings > General > OpenXR Runtime** or the current equivalent; if the app offers **Set Meta Quest Link as active OpenXR runtime**, use it for this wired PCVR session. Do not change to a different runtime silently. Verify the Link environment is actually visible in the headset and the PC app recognizes it.
   - If it fails: check cable data support, USB port, headset and PC updates, compatible GPU, permission prompts, Link vs Air Link mode, active runtime, and restart the app/session if appropriate. Recheck rather than guessing.
10. Resolve missing pieces one at a time. Re-run **live Unity MCP reads** after package/restart changes. Distinguish installed (PRESENT), enabled (ENABLED), prefab resolved (READY), device detected (DETECTED), Link session (ACTIVE), and physically validated (STUDENT CONFIRMED).

### C. Stop for student self-check (mandatory)

11. Report a compact table: **XR Management / Standalone OpenXR / Initialize XR in VR copy / Meta Core / resolved tracked-camera prefab / Unity Console / USB device / PC Link session / OpenXR runtime**. For each: `PASS`, `MISSING`, `FAILED`, or `NOT VERIFIED`, with version/path and the exact action needed.
12. Ask the student to **personally confirm**: (a) Meta/Core prefab is visible and the Unity Console is clear; (b) Standalone OpenXR has no unresolved required project validations; (c) headset is on and shows the **PC Link environment** with working head tracking; (d) the desktop scene remains saved/unchanged. If no headset is available, report `DEVICE NOT VERIFIED` and keep 02_2 blocked for real-headset acceptance.
13. **STOP.** Do not alter camera hierarchy, enter Unity Play, or invoke 02_2. Once the student reports the above checks, tell them to **separately copy `Prompts/02_2_Attach_Driver_Camera_And_Test.md`**.

Evidence standards: editor/project reads prove configuration; **only the student wearing an HMD** can confirm stereo view, visibility, and comfort. Historical reference scenes and archived reports are not live headset evidence.
